1- Technology : SOAP Web Services using JAX-WS (Java API for XML Web Services)

SOAP provides a high level of abstraction and strict contract enforcement, which is ideal for a structured system like a Chat Room. Because it relies on standardized XML messaging, it is inherently platform and language-agnostic. This ensures that users can seamlessly consume the service using software written in different programming languages (Python, Java , JavaScript) without worrying about underlying implementation details. 


2- Formal Language: WSDL (Web Services Description Language) combined with XML Schema (XSD)

WSDL is the industry-standard formal language used to describe the operations, message formats, protocols, and endpoints of a SOAP web service. XSD is used alongside it to strictly define the data types of the messages being exchanged. Together, they provide a rigid, machine-readable contract that ensures both the client and the server have an exact, shared understanding of the data structure and available operations.

3- Contract Definition in Favorite Language 

Chosen Language: Java (using JAX-WS and JAXB)

Java is my preferred language and the implementation language for this project, I defined the contract using a Java interface. By annotating the interface and its methods with JAX-WS annotations (@WebService, @WebMethod) and using JAXB for data binding, the JAX-WS tooling (wsgen) automatically generates the formal WSDL and XSD files from this Java code. This approach allows me to define the contract in a familiar language while still producing the required formal XML specifications.
